# Introduction
Consistent hashing solves the problem in hash partitioning when we add a new server.

Instead of calculating:
```
hash(key) % number_of_servers
```

where key is a primary key (some unique column in a table, e.g. `userID`), we create a hash ring which is a circle with all possible values that can be generated by the hash function:
```
		 0
	/         \
 270             90
	\         /
		 180
```

Then, we place servers on the ring. Each server gets assigned a value from all the possible values that hash can generate:
```
		 0
	/         \
 C (270)      A (90)
	\         /
	   B (180)
```

Now for each key, we calculate `hash(key)` which gives a position on the ring. We assign that key to the server which is closest to that position on the ring going clockwise. 

So for example, value 170 would be closest to the server B with assigned value 180.
# Adding a new server
When we add a new server, we place it between two existing servers, for example we add a server D like that:
```
		 0
	/         \
 C (270)      A (90)
	\         /
  B (200) - D (130)
```
So a new server D goes between A and B so now we need to move only the key on A and B, not on all the servers.
